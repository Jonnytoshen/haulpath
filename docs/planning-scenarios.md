# 规划方案草案

规划方案是项目内用于组织选址资料和分析结果的整体，与线路测算得到的“路线方案”分开。当前提供草案的创建、选择、改名、删除和重开；资源录入、计算、冻结及比较由后续功能逐步交付。

## 页面与保存

进入项目后仍默认显示线路总览，项目导航提供“规划方案”和“项目点位库”入口。规划方案列表可新建、打开及刷新草案，当前方案摘要显示所属项目、名称、输入版本、草案状态和保存时间。所有草案由本机服务保存，更换浏览器后重新选择项目和草案即可继续。

输入上下文变化时 `inputVersion` 递增；改名保持输入版本。每次保存另以 `revision` 检查并发，删除也需要当前修订号。发生冲突时重新加载后核对资料，再决定保存或删除；失败不会留下部分变更。

## 公开接口

所有路径均以 `/api/projects/:projectId/scenarios` 开始，只允许操作该项目所属的草案。项目不存在、方案不属于该项目或已经删除时返回 `404`。

| 方法与路径                               | 用途                                                   |
| ---------------------------------------- | ------------------------------------------------------ |
| `GET /`                                  | 列出该项目的草案                                       |
| `POST /`                                 | 创建草案，提交 `{ "name": "北区首期" }`                |
| `GET /:scenarioId`                       | 读取完整草案                                           |
| `PATCH /:scenarioId`                     | 提交 `expectedRevision` 及需要更新的 `name`、`context` |
| `DELETE /:scenarioId?expectedRevision=1` | 按当前修订号删除草案                                   |

创建成功返回 `201`，更新和读取返回 `200`，删除返回 `204`。无效输入返回 `400`，修订号冲突返回 `409`。稳定标识、项目归属、状态和版本由服务端维护，不接受客户端改写。

草案初始 `status` 为 `draft`，`inputVersion`、`revision` 均为 `1`。版本化 `context` 包含 `schemaVersion: 1`、`resources: {}`、`annual: []`、`results: []`；后续工单在此容器中引入具体模型。当前 `PATCH context` 保存整份草案上下文，任何上下文变更均产生新输入版本；`results` 仅为扩展资料容器，不是可信计算结果发布入口，后续计算功能须单独校验及绑定结果版本。上下文容器的版本与 SQLite schema 版本分别维护；未知上下文版本不会被当前应用静默改写，空资源及空结果不表示物理或财务分析已经就绪。

## 升级与边界

SQLite schema 3 新增草案存储，升级保留 schema 2 的项目、线路、点库、成功路线方案及偏好记忆；删除项目时同时删除所属草案。数据库中出现未来版本时拒绝打开，不降低版本号。备份和回退遵循[运行维护](operations.md)。

本轮没有接入新的高德请求或运输、站网、财务计算。既有普通驾车测算继续遵守：**未校验重卡限高、限重及货车限行**。
