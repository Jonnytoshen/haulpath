# 规划方案与版本

规划方案是项目内用于组织选址资料和分析结果的整体，与线路测算得到的“路线方案”分开。当前提供草案的创建、选择、改名、删除和重开，以及冻结、复制、显式引入资料与输入比较；支持从本项目线路建立并确认[运输循环](transport-cycles.md)，维护[运输需求与区间日货流](transport-demands.md)及[车辆组、电池与运营模板](fleet-operations.md)；项目级[电源接入点](power-connection-points.md)独立维护，方案内支持[候选站址、站型及人工固定布局](fixed-station-layout.md)；已提供[有向道路异步准备及复用](directed-road-data.md)，支持[逐车运输日计划](daily-transport.md)的时间、载荷与运量缺口试算，补能及财务结果由后续功能逐步交付。

## 页面与保存

进入项目后仍默认显示线路总览，项目导航提供“规划方案”和“项目点位库”入口。规划方案列表可新建、打开及刷新草案和冻结版本，当前方案摘要显示所属项目、名称、输入版本、草案或冻结状态、复制来源和保存时间。所有草案由本机服务保存，更换浏览器后重新选择项目和草案即可继续。

输入上下文变化时 `inputVersion` 递增；改名保持输入版本。每次保存另以 `revision` 检查并发，删除也需要当前修订号。发生冲突时重新加载后核对资料，再决定保存或删除；失败不会留下部分变更。

## 公开接口

所有路径均以 `/api/projects/:projectId/scenarios` 开始，只允许操作该项目所属的规划方案。冻结版本可读取、比较和复制，所有修改（包括改名、删除和专用输入保存）返回 `409`。项目不存在、方案不属于该项目或已经删除时返回 `404`。

| 方法与路径                               | 用途                                                   |
| ---------------------------------------- | ------------------------------------------------------ |
| `GET /`                                  | 列出该项目的方案版本                                   |
| `POST /`                                 | 创建草案，提交 `{ "name": "北区首期" }`                |
| `GET /:scenarioId`                       | 读取完整草案                                           |
| `PATCH /:scenarioId`                     | 提交 `expectedRevision` 及需要更新的 `name`、`context` |
| `DELETE /:scenarioId?expectedRevision=1` | 按当前修订号删除草案                                   |

创建成功返回 `201`，更新和读取返回 `200`，删除返回 `204`。无效输入返回 `400`，修订号冲突返回 `409`。稳定标识、项目归属、状态和版本由服务端维护，不接受客户端改写。

草案初始 `status` 为 `draft`，`inputVersion`、`revision` 均为 `1`。版本化 `context` 包含 `schemaVersion: 1`、`resources: {}`、`annual: []`、`results: []`；运输循环和运输需求分别使用可选 `transportCycles`、`transportDemands` 数组，车辆与运营资料使用可选 `operations` 对象，站网资料使用可选 `stationNetwork` 对象，道路偏好使用可选 `roadSettings` 对象，旧草案缺省这些字段；其他具体模型由后续工单引入。当前 `PATCH context` 保存整份草案上下文，任何上下文变更均产生新输入版本；`transportCycles`、`transportDemands`、`operations`、`stationNetwork` 与 `roadSettings` 由专用接口维护，通用上下文保存必须原样保留这五个字段；`results` 仅为扩展资料容器，不是可信计算结果发布入口，后续计算功能须单独校验及绑定结果版本。上下文容器的版本与 SQLite schema 版本分别维护；未知上下文版本不会被当前应用静默改写，空资源及空结果不表示物理或财务分析已经就绪。

## 冻结、复制与比较

- `POST /:scenarioId/freeze` 提交 `{ "expectedRevision": 3 }`，返回冻结版本。冻结时间和修订号由服务端维护，输入版本不变；不可解冻或直接删除。
- `POST /:scenarioId/copy` 提交 `{ "expectedRevision": 4, "name": "调整草案" }`，返回 `201` 新草案。草案及冻结版本均可复制；复制保留当前全部输入和局部关联，清空非正式结果容器，不修改来源。新身份的输入版本、修订号均从 `1` 开始。
- 返回的 `lineageId` 表示共同沿革，`copiedFrom` 保留直接来源的 `scenarioId`、`name`、`inputVersion`、`revision`。`frozenAt` 为冻结时间或 `null`。旧资料读取时补齐缺省值，不因此增加输入版本。
- `GET /compare?left=:scenarioId&right=:scenarioId` 在同项目内比较两个版本。返回 `{ left, right, differences }`；差异项含 `kind`（`added` / `removed` / `changed`）、`section`、`path`、`label`、`left`、`right`。按身份对齐循环、需求、车辆、站型、站址和电源，顺序单独展示；包含来源、参数、其他资源及年度输入。不同名称不等于不同业务输入，采集时间和非正式结果不作为输入差异。
- 版本身份由请求路径确定，修订号检查目标版本。切换版本不会将旧请求重定向；冻结与任何保存竞争时，事务内重新检查修订号及只读状态。项目删除仍整体删除所属版本。

## 显式引入共享资料

源线路和项目电源变化均不会自动改写方案。`POST /:scenarioId/cycles/:cycleId/source` 提交 `{ "expectedRevision": 3 }` 显式引入源线路的最新输入及路线方案。操作采用源顺序和偏好，移除方案内手工补点并取消业务确认；保留循环身份和仍存在的来源点位位置身份，重复来源身份按出现顺序保留各自位置身份，保留失效需求及运营输入，提示重新补回程、确认和修复。没有实际来源变化时不写入，也不产生伪输入版本；来源已删除时返回 `404`，方案快照继续保留。

项目电源仍在站网维护中逐项显式引入，沿用[人工固定站网](fixed-station-layout.md)的来源修订号竞争检查与确认失效规则。普通输入编辑不刷新项目源。冻结版本先复制成草案，再引入共享资料。

版本与快照取舍见 [ADR 0007](adr/0007-frozen-scenario-version-lineage.md)。此阶段比较输入，不提供物理、财务指标或收益排序。

## 升级与边界

SQLite schema 3 新增草案存储，schema 4 新增独立项目电源资源，schema 5 新增独立道路任务及项目缓存，schema 6 新增独立运输任务及正式结果。升级保留项目、线路、点库、成功路线方案、规划草案及偏好记忆；删除项目时同时删除所属草案和电源资源。数据库中出现未来版本时拒绝打开，不降低版本号。备份和回退遵循[运行维护](operations.md)。

道路准备由用户显式启动；运输时间与载荷通过独立任务生成，不能据道路就绪判断站网可行性或财务；补充点位复用既有坐标转换接口。既有普通驾车测算继续遵守：**未校验重卡限高、限重及货车限行**。
