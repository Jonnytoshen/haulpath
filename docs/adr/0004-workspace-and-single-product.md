# 使用单应用工作区与领域源码包，保持单一产品版本

重途已有前后端共用的领域类型与规则，但尚无第二应用或独立服务需求。采用 pnpm workspace 与 Nx，将完整 Next.js 应用保留在 `apps/web`，只提取 `packages/domain` 的平台无关领域代码；应用以 `workspace:*` 直接消费 TypeScript 源码，由 Next.js 转译，避免为当前唯一消费者维护预构建、监听和额外部署流程。业务仍是一个上下文，共用根术语表与既有领域 ADR。

Nx 显式编排根命令，应用检查和构建依赖领域检查；首轮仅缓存无产物的领域类型检查，应用检查、webpack 构建及所有测试每次实际执行。共享应用产物的任务在同次调度中禁止并行，独立命令仍须串行。根适配层保留参数、信号、环境文件优先级和以仓库根目录解析数据库的行为，用户配置与资料无需搬迁；Docker 保持原 Compose 与数据卷身份。

根 `haulpath` 继续是唯一版本与发布对象，两个子包私有且无独立版本。根在 Nx 中对两个子包配置隐式依赖，使仅修改应用或领域包的提交也参与产品版本和统一日志分析，沿用现有领域 scope、`v{version}` tag 与候选恢复协议。代价是需要维护根启动适配层和跨工作区构建追踪，并持续从真实根命令、应用、发布和容器入口验证兼容性。操作与验收见 [README](../../README.md)、[发布指南](../releasing.md)和[验收记录](../acceptance.md)。
