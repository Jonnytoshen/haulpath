# 冻结版本以独立方案身份保留，复制后继续编辑

规划方案的输入版本已经用于区分输入与对应结果；冻结又需要永久保留某次决策依据。采用现有规划方案身份作为可独立读取、归属项目的版本身份，冻结后所有方案写入口均拒写；继续调整时创建新身份的草案，记录共同沿革及直接复制来源的名称、输入版本和修订号。没有另设可变的“当前版本”指针，避免迟到请求写到刚切换的版本。旧草案读时补齐沿革信息，不改输入版本或 SQLite schema。代价是项目列表同时包含草案及冻结版本，复制来源删除后仍保留来源记录；删除整个项目仍删除其全部方案。

复制保留全部当前输入快照及方案内关联身份，身份以所属方案为边界；不复用结果容器中的资料作为新草案的计算结论。新草案从输入版本及修订号 1 开始，与来源独立。冻结只增加修订号和冻结时间，输入版本保持不变；不存在解冻写入口。后续任务必须按项目、方案身份和输入版本绑定不可变快照，结果不得通过通用上下文容器发布为正式结论。

共享资料仅在用户显式引入时改变方案。线路更新采用最新源线路的点位顺序、偏好及来源路线方案，保留循环身份与仍存在的来源点位位置身份，重复来源身份按出现顺序匹配；移除手工补点，取消业务确认，保留需求和运营输入，以既有就绪规则提示失效依据。与仅更新来源标记相比，这能使采用的资料与来源一致，代价是用户须重新补回程及核对关联。相同来源资料重复引入不形成伪版本；电源更新继续使用既有站网快照与确认失效契约。

输入比较在一个契约内按稳定身份对齐当前已支持的循环、需求、运营、站网、其他资源和年度参数，顺序单列，排除只表示采集时刻的循环时间戳及未验证的结果容器。后续资源扩展同一比较入口；结果和财务指标由后续工单加入，不能据当前输入差异给出能力或收益排序。
