# 用连续排程证据认证代表日周期，而非按日重置电池

固定布局的首日试算从满电开始，不能据此证明每天都能恢复。周期阶段复用现有运输生成器、车辆能量搜索、到站队列、站内连续充电及共享电源日历，先对执行运输的车辆寻找出发与归位能量一致的换电安排，再把同一份业务计划平移到连续的构造区间。站内库存只在构造起点初始化一次，期间不重置；排队继续传入车辆事件。与另写一个稳态模拟器相比，这保留了既有时间、载荷、能量和充电规则，代价是正式结果需要保存可供独立重放的有限构造证据。

有限构造本身不是周期证明。校验器逐个重放构造区间的车辆、工位、库存、充电和共享电源；核对末端相邻三个业务计划的车辆事件与连续充电安排均为严格 1440 分钟平移；另从事件计算中间代表日两端的车辆位置、作业剩余时间和电量，以及每站满电数、待充电量、在充电量与剩余预订时间、服务中领出的电池及工位进度。只有状态等价、无跨日同车冲突，且所有阶段均通过独立校验，才认证可重复并发布完整物理可行候选。服务期间领出的满电池单独计入站内资源，旧电池在服务结束才回收，防止跨零点漏记或重复记能量。

周期边界固定为本日零点至次日零点，而车辆出发/归位锚点仍由班次决定；跨午夜事件保持完整。购电只积分充电与 `[0,1440)` 的交集，包括零点前已开始的充电，不把窗口外或未开始的需求算作购电。周期初末总储能及日内耗电、补入电量同时对账。结果中的车辆时间轴沿班次锚点展示，站账与电源账沿日历零点展示；有限构造证据另存以供发布重放。

启发式在固定车次与班次内要求有正耗电的车辆至少一次换电，以其归位电量迭代出发电量，最多 32 次。站内构造依次尝试 4、8、16、32 份平移计划，并保留最后班次之后的一天供连续充电收尾。起点采用满电仅用于寻找稳态；未检查到完整边界等价时，即使若干天可运行也不能认证周期。算法和数值政策可随版本更替；本版时间容差为 `1e-7` 分钟，能量比较为数值尺度的 32 倍机器精度，有正耗电且无换电不能以舍入后的首尾相等冒充闭合。

这是一种有界、可重放的候选构造，不保证找到所有闭合状态或最优排程。失败说明本次未找到闭合状态，不能证明全局无解；也不是连续多日运输执行或按日新增业务的模型。旧四个阶段保留首日语义及 `not-established` 物理状态。只有新 `repeatable-day` 阶段通过组合校验才可标为 `feasible`，财务仍单独校核。任务继续遵守 [ADR 0009](0009-daily-transport-worker-and-results.md) 的不可变快照、队列和事务发布；主线程发布时再次重放周期证据。
