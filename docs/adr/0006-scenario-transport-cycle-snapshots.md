# 规划方案中的运输循环使用独立线路快照

规划方案需要复用已整理的线路，同时允许在方案内补回程和调整业务顺序。若直接关联可变线路，后续改点或重新测算会无声改变规划输入；若只复制名称和坐标，又无法追溯道路资料的来源与方向。

从本项目线路引入运输循环时，同时保留来源标识、输入版本、点位、规划偏好及路线方案快照。循环独立维护点位顺序和偏好，每次点位出现有独立位置标识，包括 A→B→A 的两次 A。原线路后续改动或删除均不自动同步，避免把来源维护变成方案输入变更。

仅在源路线方案仍匹配源输入版本时引入有效道路资料；后续复用还须匹配起止位置、方向、坐标和偏好。回程不通过反转去程折线产生。业务顺序与回程须显式确认，确认状态和道路、时长就绪缺口分别判断，不能把闭合循环视为完整物理可行结论。既有[完整路线方案快照原则](0002-segment-planning-and-result-snapshots.md)继续适用。

循环保存在 SQLite schema 3 的规划方案版本化上下文中，沿用事务与修订号检查，通过专用公开接口维护。通用上下文更新只能原样保留循环，防止绕过来源归属及确认校验。代价是保留重复的来源资料，并需显式引入更新；冻结、复制和显式资料更新的工作流由后续功能交付。
