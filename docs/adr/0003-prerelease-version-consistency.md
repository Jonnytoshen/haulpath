# 候选版本与正式版本保持相同基版

## 背景

发布候选用于验证预期正式版本。Nx 原生预发布状态推导不能直接代表从最近正式 tag 以来的累计最低正式版本；若从磁盘候选版本继续递增，可能对同一破坏性变化重复提高基版，或在转正时产生未经过候选验证的新基版。

## 决策

采用 Nx 公开发布 API 的独立只读推导，从最近正式 tag 分析累计提交，显式使用正式 tag 解析和空预发布标识，不继承候选渠道、首次发布回退或候选清单版本。候选基版取已有候选基版、累计自动最低版本和合法手动目标的最大值，再将精确目标版本交给 Nx 执行实际版本、日志和本地 Git 操作。

同基版渠道按 `alpha → beta → rc → stable` 前进，允许跳级，禁止倒退；新基版或新渠道的编号从 0 开始。转正只移除候选后缀。若累计变化超过当前候选基版，先发布符合下限的新候选，再转正；已预留足够高的基版保持不变。首发先显式建立 `0.1.0` 正式基线。

## 取舍

维护者验证过的候选和最终正式版具有相同基版，累计破坏性变化不会被重复递增；手动目标仍受自动下限约束。代价是需要在 Nx 外维护精确的候选计划与状态检查，超过下限的变化可能要求多一次候选发布，不能完全照搬 Nx 原生预发布推导。

该决策只涉及软件发布 SemVer，不改变 SQLite 结构版本、测算输入版本或既有领域 ADR。命令、示例与恢复约定见[发布指南](../releasing.md)；运行验证状态由发布验收单独记录。
