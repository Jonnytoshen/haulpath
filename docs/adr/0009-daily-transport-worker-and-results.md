# 运输试算以应用 Worker 运行，任务固定道路与独立正式结果

逐车运输计算会执行反复候选构造和约束核对，继续放在应用主线程会影响普通页面与资源接口；新增独立服务又会增加本机部署及数据归属成本。选择同一 Next.js 应用内的 Node Worker：主线程持有 SQLite、单运输任务队列与发布权限，Worker 只消费不可变输入并执行纯计算。道路准备仍沿用独立的有界网络请求队列。

任务在创建事务中固定方案上下文与当前版本显式准备后实际采用的道路，记录项目、方案、输入版本、任务身份、算法版本、种子和配置。与 Worker 运行时读取缓存相比，这使结果可追溯，代价是任务快照占用更多存储。结果经独立运输校验后，在事务内再次检查活动状态和当前版本才接纳；所有 Worker 消息也检查完整归属。复制不继承任务，冻结后不接受迟到发布，遵循 [ADR 0007](0007-frozen-scenario-version-lineage.md) 与 [ADR 0008](0008-directed-roads-and-task-snapshots.md)。

使用专门任务表持久化正式结果，通用上下文结果容器继续不具有发布权限。任务摘要和较大的快照、结果分开存储，轮询、状态检查及进度更新只访问摘要。运输校验与补能、物理和财务就绪分别表达，当前只交付运输时间及载荷构造。有限贪心算法不保证最优或证明无解，避免把本阶段完成误当作全模型可行。

Worker 引用领域 TypeScript 源码，由应用入口用 esbuild 打成 Node 22.12 JavaScript，普通构建、开发、真实测试启动、standalone 与 Docker 均交付同一产物；开发任务启动前另起编译进程采用源码更新。与 Node 直接执行 TypeScript 或领域预构建相比，这保留 [ADR 0004](0004-workspace-and-single-product.md) 的领域源码消费方式及最低 Node 边界，代价是增加一个应用构建产物和开发重建步骤。详细契约见[逐车运输日计划](../daily-transport.md)。
