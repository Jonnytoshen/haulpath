# 资产与资本收付

规划方案内打开「资产与资金」，可独立维护资产和资金安排并核对年度资本收付，无需先完成年度能力或运营收支。账目完整只表示本阶段资料可核对，**未校核折旧、税费、融资、项目/股权现金流及 NPV**。它不改变物理可行性，普通驾车测算仍未校验重卡限高、限重及货车限行。

## 范围、年份与承担方

显式选择「一体化」或「仅站方」及初始建设年份、资产评价年份。建设年份必须为评价首年；年份为1至9999的唯一整数，可不连续。已有年度能力输入时必须覆盖其全部年份，仅允许额外增加首年建设期；不另建脱节的财务年限，也不默认年份、天数或寿命。没有年度物理输入时可先独立维护；后续年份变化须显式修复。

范围依据须说明全部资产及营运资金是否已列明，没有相应项目也须声明。资产分别声明站方、运输方或外部取得/承担：一体化纳入站方与运输方，仅站方只纳入站方，外部项目列示但不加入本边界合计。未声明归属、范围或业务边界保持不完整；已有运营收支边界不一致时明确列出待统一缺口。

## 分类资产与资本事件

资产分类为车辆、电池、站点设备及建设、接电工程、其他资产；保存稳定身份、取得方式、取得金额、投运年份、来源、资产范围说明及可选站址和预算归集。新身份由服务端生成，既有身份必须属于本方案，不以同名资产重绑。

- 本次新增：只在初始建设年列一次初始支出，投运年份须为该年，遵循一次建成投运的固定规模。金额为整项总额，无隐含数量或默认单价。
- 历史已发生：投运年早于本期，取得金额只作为历史资产依据，不再自动列本次初始支出；后续显式更换与处置仍按承担方纳入。
- 更换：显式填写投运后的评价年份、新设备投资、旧件回收和共同来源，无旧件回收须填0。更换不自动加车、扩站或修改电池库存。
- 末期残值：显式填写评价末年、金额和来源；未填写保持未知，无回收价值须明确填0。不按寿命或残值率推算，也不将残值误作折旧。

没有自动折旧、税务抵扣或融资处理。分类、投运时间、原值、更换和回收依据保留给后续税费票；历史原值不是已经确认的计税基础。

## 站网预算对账

采用当前输入版本完整站网快照，逐个固定布局站址将新增分类资产与所选站型完整建站投资、接电工程投资分别对账。站型完整投资已经包含必要备电池等全部新建配置；分类电池及站房设备是其分拆，不能再额外加一次站型总价。接电工程只在接电分类计一次。各承担方均参加工程预算对账，再由业务边界决定现金流纳入范围。已有资产不充作本次新增工程投资。

关联站址的站点设备、备电池和接电资产须归入相应预算；站点和接电分类必须关联固定布局站址。无分类、站网缺价或分拆差额保持缺口；页面展示预算、分类金额和差额，预算自身**不再加入现金支出**。车辆、后续更换、营运资金不属于既有选址新增投资上限。金额变化须通过站网专用接口显式采用并遵守确认失效、预算和布局硬约束；资产字段及人工替代不放宽物理规则。

## 营运资金与年度替代

按承担方输入期初占用余额及来源、每个评价年期末余额和来源。年度增加为本年期末大于期初的差额，减少为释放；下一年期初采用上一评价年期末。没有年行、金额或来源时保持未知，不跳过缺年连接首尾，也不每年重复扣同一余额。首年期初占用是已有占用依据，不作为本次新增支出。末年不自动恢复，全部恢复须显式录入期末0。不依赖收入比例或运营结果。

特殊年度替代的唯一目标为「资产身份＋年份＋资本事件（初始、更换、旧件回收、末期残值）」，采用替代金额，保留基准值、原因和来源；两笔不叠加。覆盖金额也可未知，不能冒充零。原因及来源不能为空，重复目标或非法字段整批拒绝；目标被移除后保留缺口供修复。初始替代后的金额也必须与工程预算对账，不能借替代规避预算。营运资金特殊安排直接修改明确的年度余额及其来源。

## 数值政策

`cny-asset-line-half-up-6-2-v1`：非负金额以十进制文本录入，最多12位整数、6位小数；`null`为未知，`"0"`为明确零。每项资本事件、历史金额及资金余额先用十进制 BigInt 四舍五入至分，余额相减及年度归集均用整数分，不做浮点累计。年度收入/流出方向由事件决定，不用负金额混写。年度收付分别为更换/初始投资与资金增加，以及旧件回收/残值与资金释放；余额为流入减流出。金额和总和须为安全整数分，溢出和未知保留逐项依据，不发布完整年度总数。

站网已有 number 金额沿用15票的逐项分位舍入政策对账；不改变旧投资预算算法，也不以本阶段精度限制追溯拒绝旧站网资料。站型和接电预算分别逐项舍入后与分类资产相比较。两笔0.005和0.015元新增投资各舍入1和2分，合计3分；期初及期末资金余额也分别舍入，再计算其差额。

独立三年案例：首年新增周转电池1000元，历史车辆5000元及外部设备900元不产生本边界初始支出。资金期初0，三年期末分别100、120、0元。次年更换400元、旧件回收50元，末年残值80元。年度流出/流入/余额为1100/0/−1100、420/50/−370、0/200/200元。次年更换用有原因的350元替代时，该年流出370、流入50、余额−320元。末年余额保持120而非0时不自动释放。

## 持久化、版本与接口

正式 `assetCashflows` 输入只能通过专用接口整批保存。修订冲突、非法精度/身份/重复/字段均原子拒绝；缺失资料可保存草稿并列缺口。真实变化推进输入版本，相同完整输入不制造版本。站址退出布局后保留失效身份；源资料不自动改写资产。

核对在短 SQLite 事务中重新检查修订、归属及冻结，发布独立不可变账目至 schema8 `asset_cashflow_results`，绑定项目、方案、输入版本、资产输入和完整站网快照。沿用同一数据库的备份恢复。旧版本结果保留并显示历史；冻结可读但拒绝输入及新结果，复制保留输入身份和沿革、不继承新方案结论。通用 `results` 不发布本阶段正式账目。

资产字段仅是财务安排，年度代表日等价及17的旧物理证据显式采用比较明确排除 `assetCashflows`；站网投资、车队及全部其他物理输入仍比较。修改资产不重写源任务、不拼接不同年度任务，不改变已有经济状态。详见 [ADR 0011](adr/0011-operating-cashflows-and-evidence-adoption.md)。

前缀 `/api/projects/:projectId/scenarios/:scenarioId/asset-cashflows`：

| 方法           | 契约                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| PUT /          | `{ expectedRevision, input: { boundary, initialYear, years, scopeSource, assets, workingCapital, overrides } }`，原子保存并返回完整方案 |
| GET /          | 当前输入版本、基本缺口和按创建倒序的正式/历史结果                                                                                       |
| POST /         | `{ expectedRevision }`，有界归集，无需物理或运营结果，不启动 Worker；返回201账目，不完整也明确记录缺口                                  |
| GET /:resultId | 仅读取本方案的独立账目，归属不匹配404                                                                                                   |

每张列表最多1000项，单个文本最多2000字。资产新项省略 `id` 或填空串，已有项携带服务端身份。`replacements` 为 `{ year, amount, disposal, source }`，`residual` 为 `{ year, amount, source }` 或null。资金账户为 `{ owner, openingBalance, source, years: [{ year, balance, source }] }`，同一承担方一个账户。替代为 `{ assetId, year, kind, amount, reason, source }`。

表单支持全部字段，资产和资金分别支持TSV预览后采用。资产追加新明细，资金仅替代预览涉及承担方的计划；预览采用保留期间对范围或其他类别的编辑。非法预览不产生可采用资料，最终仍统一保存并由公开接口校验。不新增文件导入或财务导出。
