# 候选站址、站型与人工固定布局

规划方案中的“人工固定站网”用于维护新建候选站址、离散站型和方案采用的电源资料，再人工选定一套固定布局。站址与项目电源接入点是独立对象，距离近不表示场地或接电条件已经确认。当前维护输入和就绪缺口，不生成道路资料、运输排程、共享供电校核或财务结论。**未校验重卡限高、限重及货车限行**。

## 录入与选择

站型包含工位数、单次换电时间（分钟）、站内电池库存、同时充电槽位数、站内总充电功率上限（kW）、服务窗口、充电窗口、建设投资（元）、年度运维费用（元/年）和参数来源。站内总功率上限与统一电池的单电池电网侧等效充电功率分别维护，在[每日计划](daily-transport.md#站内周转)中用于校核充电排程。数量须为整数；工位、换电时间及总充电功率上限填写时须为正，库存和充电位允许为零并明确提示当前不能服务。方案仍统一使用“车辆与运营”中的一种电池规格；新站型采用当前电池资料，已有站型保留原关联依据。电池资料变化后须显式重新关联，不按电池名称匹配，也不引入多规格库存。

候选站址可通过表单填写名称、原始坐标及坐标系、场地说明，通过地图补点或移动位置，并按名称和场地确认状态筛选。地图点击可补充候选；点击已有标记或该站的“地图移动”，再点击新位置或选择搜索地点，可移动该站。地图采用 GCJ-02 坐标，移动后清除场地及接电确认；未保存的 WGS84 位置须转换后才绘制。场地条件由用户明确确认；新建位置先保存为待确认，不能把一次补点当作工程条件确认。地图缺少配置或加载失败时仍可使用表单和列表。

电源资料先从本项目的[电源接入点](power-connection-points.md)显式引入方案，同一项目源在一份方案中只保留一个采用快照。再为站址选择一个接电关系，填写该站可用功率、接电投资及依据说明。每站只有一个关系，多个站允许选择同一个方案电源；本阶段不对各站同时占用共享容量作联合校核。确认接电前，电源须有正容量及容量来源，该站可用功率须为正且不超过采用电源的容量。

人工固定布局以稳定标识选择站址和站型。新增或更换选择时，站址须已确认场地和接电关系，站型物理参数与电池关联须有效；既有选择因后续编辑失效时保留，并明确列出待修复项。保存布局不表示已经生成或验证可运行的运输计划。

缺失数值保存为 `null`，不补入工程默认值或财务零价。站型投资、年度运维费用及接电投资暂缺时可保存资料和固定布局，页面单独列出财务缺口；不能据此进行完整经济排序或判断预算满足。明确输入的零金额保留为零。

时间窗口以代表日午夜后的分钟表示，开始范围为 `0–1439`，结束须晚于开始且窗口时长不超过 24 小时。结束超过 `1440` 表示跨午夜；同一类窗口不能在重复的 24 小时周期内重叠。服务窗口和充电窗口分别维护，空列表表示尚未配置，不表示全天开放。

## 页面操作与批量粘贴

打开方案后点击“维护人工固定站网”，在“候选站址 / 站型 / 电源快照 / 固定布局”四区维护同一份草稿。“保存全部站网资料”统一保存四区内容，不因切换分区自动保存。新站址、站型及引入电源须先保存取得稳定身份，再用于关联或确认。

先录入站型、候选站址并引入电源快照后保存；重开填写场地及接电依据并保存，核对原样资料后确认；最后在“固定布局”为站址选择已保存站型，再统一保存。变更资料与确认分开保存，避免把对旧依据的确认沿用到新资料上。站型的“显式重新关联当前统一电池”和电源的“显式引入项目源最新资料”分别更新对应依据；后者不能与方案内快照编辑同时执行。

候选站址与站型支持 Tab 分隔的批量粘贴，先校验并预览行号和错误，再整批加入草稿，最后显式保存。候选按新增位置处理，不自动确认或按名称合并；站型也不覆盖同名已有身份。

| 资料     | 按顺序粘贴的列                                                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 候选站址 | 名称、经度、纬度、坐标系、场地条件说明；共 4–5 列，说明可省略，坐标系空列使用 GCJ-02。                                                             |
| 站型     | 名称、换电工位、换电分钟、电池库存、充电位、站内总充电功率上限、服务窗口、充电窗口、建站投资、年度运维费用、参数来源；共 11 列，缺失资料保留空列。 |

页面及粘贴中的窗口使用 `06:00-18:00`，多个窗口用分号分隔；跨午夜须写为 `22:00-次日02:00`。留空仍表示缺失，不能以未填写代替全天开放。

## 确认失效与方案快照

项目电源资料引入后，方案保留来源标识、来源集合修订号和独立资料快照。项目源自行改名、修改容量或删除，不自动改变已采用快照、确认状态和方案输入版本；方案使用者可继续核对原依据。需要更新时显式引入当前源资料，也可只在本方案编辑采用资料，不回写项目源。

确认只对应已保存的资料依据：

- 修改站址坐标、坐标系或场地说明，清除场地及接电确认。
- 修改接电关系、电源选择、可用功率、投资或说明，清除接电确认。
- 方案采用的电源快照发生变化，或显式引入发生变化的源资料，清除引用该电源的接电确认。

修改资料的同一次请求即便带有确认标记，也不能跳过确认失效。先保存变更，再核对新资料并确认。显式更新仅改变来源集合修订号、采用电源的实际资料未变化时，不清除接电确认。

接口允许删除已被采用的站型或站址后保留既有固定布局引用，并列出缺口；页面“移除站址 / 移除站型”同时将对应选择移出草稿布局。删除方案电源后，原站址接电引用保留为失效关系，不能继续确认。新增或更换关联仍须使用当前方案内的有效身份，不按同名资料自动重绑。站型资料变得不完整、被删除或统一电池依据改变时，也须先修复相应缺口，不能把旧布局当作当前就绪布局。

## 坐标与保存

写入坐标始终使用用户声明的原始经纬度和坐标系。服务端保留原始资料及供地图使用的 GCJ-02 坐标；原始坐标和声明均未变化时复用转换结果，避免对 WGS84 重复转换。WGS84 新录或移位仍需要高德 Web 服务配置，整批校验或转换失败不写入部分资料。

站网保存在规划方案上下文中，更新须提交当前方案修订号；首次引入或显式更新电源时，事务内还核对项目源集合修订号，避免转换期间的资料变化被静默覆盖。输入变化递增输入版本和修订号，完全相同的资料不增加版本。冲突时保留本地草稿，重新加载前先核对内容。未保存时切换页面会先确认放弃，保存期间须等待完成。

## 公开接口

`PUT /api/projects/:projectId/scenarios/:scenarioId/station-network` 接收：

```json
{
  "expectedRevision": 1,
  "network": {
    "stationTypes": [],
    "sites": [],
    "powerSources": [],
    "fixedLayout": []
  }
}
```

各列表最多 1000 项，说明及来源文本最多 5000 字。整批校验后原子替换并返回完整规划方案；通过既有方案 `GET` 接口读取 `context.stationNetwork`。旧草案可没有该字段，读取不自动回写。本功能自 SQLite schema 4 引入；当前 schema 6 另有[有向道路任务与缓存](directed-road-data.md)及[运输任务结果](daily-transport.md)，上下文版本继续为 1。

| 列表           | 写入内容与规则                                                                                                                                        |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `stationTypes` | 站型物理、窗口、费用和来源；新项省略 `id`，`refreshBattery: true` 显式采用当前统一电池；不接受客户端改写 `batteryBasis`。                             |
| `sites`        | 原始坐标、场地说明、场地确认及唯一 `connection`；不接受客户端提供转换后坐标的依据字段。                                                               |
| `powerSources` | 新项按 `sourcePointId` 引入本项目源；既有项可用 `point` 编辑方案快照，或用 `refreshSource: true` 显式引入最新源，两者不能同时提供。来源身份不能换绑。 |
| `fixedLayout`  | `{ siteId, stationTypeId }` 列表；一个站址只能选择一次，不以同名站址或站型推断身份。                                                                  |

站型字段为 `name`、`bays`、`swapMinutes`、`batteryInventory`、`chargingSlots`、`chargePowerKw`、`serviceWindows`、`chargeWindows`、`investment`、`annualOperatingCost`、`source`；其中 `chargePowerKw` 是站内总充电功率上限。站址字段为 `name`、`longitude`、`latitude`、`coordinateSystem`、可选 `source`、`siteNotes`、`siteConfirmed` 和 `connection`；已有项另带 `id`。接电关系为 `{ powerSourceId, availablePowerKw, connectionInvestment, notes, confirmed }`，也可整体为 `null`。

新身份由服务端生成，已有身份须属于本方案；项目源引用须属于本项目。无效字段、重复身份或非法关联返回 `400`；项目或方案不属于请求路径、首次引入或显式更新时项目电源不存在，返回 `404`；过期修订号返回 `409`。坐标转换沿用既有服务错误边界。通用方案 `PATCH context` 必须原样保留 `stationNetwork`，不得绕过专用校验或直接写入确认依据。

## 初步候选生成与正式候选集

候选站址分区提供“生成并保存初步候选”。先保存正在编辑的站网，系统从方案已引入运输循环的每个业务位置及方案电源快照位置各提出建议，不依赖旧候选的道路矩阵或地图配置。算法 `input-locations-v1` 不沿虚构折线采样、不推断工程条件；它只是一个有限的初步位置集合，不保证覆盖所有适合建站的地点。

生成入口立即原子保存；新增站址使用新身份、`source: generated`，保留 `generationBasis` 中的来源位置身份及名称说明。原始坐标声明和已有转换结果直接沿用输入快照。建议没有场地说明、场地确认或接电关系，电源位置的建议也不自动关联该电源。同次完全相同的地图坐标只建议一次并保留各来源；已有系统建议同址时合并新来源依据而保留人工资料；已有人工候选同址则跳过。再次生成遇到同一已生成来源时跳过，保留人工移动、改名和确认；删除候选后可重新生成。来源改变后如需重提位置，先核对并移除原建议，系统不会静默覆盖。既无新增站址也无新增来源依据时不改变输入版本。

生成依据是原始建议的追溯记录，人工改名、移动及修改定位来源仍保留；客户端不能伪造或改写。地图补点、搜索、移动和表单继续使用既有草稿及确认失效流程。新增或移动后须为新输入版本准备相应道路资料，旧道路仅按精确起止、方向与偏好复用。

正式候选集由当前场地、接电确认及有效供电资料共同确定，并排除禁选站址；与人工固定布局分开。场地或电源条件变化后，确认失效的站址退出正式集合，保留原选择与修复缺口。页面的名称、场地状态、正式候选及禁选筛选仅改变列表和地图显示，不写入输入；持久排除使用“选址约束”的禁选条件。草稿位置仍可提前准备进出站道路；禁选位置从当前道路需求范围排除，历史任务快照保持原范围。必选不是工程确认，未进入正式集合的必选站址明确列为冲突。

## 选址硬约束与投资口径

站网的可选 `constraints` 为 `{ maxInvestment, maxStations, requiredSiteIds, excludedSiteIds }`。金额上限单位为元，站数上限为非负安全整数；两个上限使用 `null` 表示不限制，明确的 `0` 始终生效。必选与禁选使用本方案站址身份，不能同时指定同一身份，不能重复或引入其他方案身份。已有约束引用的站址删除时保留失效引用，须显式移除或修复；不按同名站址重绑。旧方案无约束时沿用无限制；保存时省略 `constraints` 保留原约束，清空四项才显式取消。

新增投资按每站所选站型的 `investment` 加该站 `connectionInvestment`，逐项四舍五入至分后求和（安全整数分位范围内）。建站投资须由用户填写完整新建配置（包括备电池及其他必要建设投入），接电投资只计该站供电工程投入，避免重复；年度运维不计入本上限。本口径不提供资产分拆、后续更换投资、融资或年度现金流。

启用预算时，所有正式可选站址的接电投资、全部物理资料就绪站型的建站投资，以及当前布局涉及的金额必须明确且在金额范围内；缺价则拒绝本次保存，不能用零或市场默认值补齐。年度运维缺失不阻止预算核对或物理分析。新增预算范围前需先补齐价格，或显式关闭预算以维护草稿。无预算时缺价继续保留财务缺口，允许物理分析。

资料或约束调整使原布局违反站数、投资、必选或禁选时，可保存为待修复草稿，页面及每日试算就绪项列出冲突；新增/更换布局选择须完整满足硬约束，否则服务端拒绝原子保存。每日任务启动和独立补能/周期校验继续校核约束，不会把冲突草稿发布为完整物理候选。本票不联合搜索站址或站型，仍为人工固定布局。

`POST /api/projects/:projectId/scenarios/:scenarioId/station-network` 接收 `{ expectedRevision }` 并返回完整方案；无新增建议也返回原方案。过期修订或冻结返回 `409`，跨项目归属返回 `404`，生成超过1000个候选时整体拒绝。专用 `PUT` 增加可选 `constraints`，已有站址可原样携带 `generationBasis`；生成依据由服务端保留，不接受新增或修改。字段仍由通用上下文保护，冻结、复制、比较及任务输入版本绑定均沿用现有契约。
