# 方案内运输循环

在项目的“规划方案”中打开草案，选择“从线路建立循环”。来源只可选本项目线路；引入点位顺序、普通驾车规划偏好、已有路线方案和来源版本快照。未规划或待重算的线路也可引入，但旧路线方案仅保留为来源，不计入有效道路资料。

## 补齐与确认

循环内每次点位出现使用独立、稳定的位置标识，例如 A→B→A 的两次 A 分别保留身份，不按名称或坐标合并。编辑循环时可以维护业务顺序及回程；保存后由本机服务持久化。源线路后续改名、改点、重新测算或删除均不会自动覆盖已有循环。

首尾坐标相同表示空间闭合，仍须显式勾选“已核对业务点位顺序与闭合回程”。确认要求至少两个不同地点并返回起点，且不允许相邻坐标重合。确认只表示业务安排已核对；道路资料和行驶时间不足时继续显示“就绪缺口”。改变业务点位或规划偏好后须重新确认，仅改循环名称保留确认。

已有道路只用于原位置身份、方向、坐标和规划偏好均匹配的相邻区间。补齐回程不会反转去程折线或复制去程里程，改变顺序也不会生成示意道路。补充点位支持声明 GCJ-02 或 WGS84，复用既有坐标转换；[道路准备](directed-road-data.md)可显式补齐缺失有向道路，不改写引入快照；不提供运输排程或物理可行性结论；行驶时间可由[运营速度模板或有效区间实测](fleet-operations.md)补充，按可用车辆组分别判断缺口。**未校验重卡限高、限重及货车限行**。

## 公开接口

路径前缀为 `/api/projects/:projectId/scenarios/:scenarioId`。

| 方法与路径                                   | 请求                                                             | 返回                            |
| -------------------------------------------- | ---------------------------------------------------------------- | ------------------------------- |
| `POST /cycles`                               | `{ sourceRouteId, expectedRevision }`                            | `201`，更新后的完整规划方案     |
| `PATCH /cycles/:cycleId`                     | `{ expectedRevision, name?, strategy?, positions?, confirmed? }` | `200`，更新后的完整规划方案     |
| `DELETE /cycles/:cycleId?expectedRevision=N` | 当前修订号                                                       | `200`，删除循环后的完整规划方案 |

新增位置使用 `{ point }`，已有位置使用 `{ id, point }`。`point` 遵循既有点位契约，保留已转换坐标和原始坐标及坐标系，不在循环接口重复转换。循环和位置标识由服务端生成；已有位置标识只能属于当前循环，列表内不能重复。来源、道路资料和确认时间由服务端维护，客户端不能直接改写。

每次有效变更原子递增规划方案的 `inputVersion` 与 `revision`。旧修订号返回 `409`，无效输入返回 `400`；跨项目方案、来源线路、循环或已删除对象返回 `404`。任一错误均不留下部分变更，也不修改源线路及项目偏好记忆。

## 保存结构与兼容

循环保存在版本化上下文的可选 `transportCycles` 数组中；旧草案缺省此字段，读取不改变旧资料。本功能自 SQLite schema 3 引入；当前 schema 6 另有项目电源、独立道路资料及运输任务结果存储。

- 循环保存名称、偏好、点位位置、来源、道路、确认状态及确认时间。
- 来源保存 `routeId`、线路名称、`inputVersion`、点位、偏好、原路线方案与 `importedAt`。
- 位置保存独立 `id`、点位快照与可追溯的 `sourcePointId`；新增回程位置没有来源位置标识。
- 道路资料关联有向的起止位置标识及偏好，保留原区间快照。

通用 `PATCH context` 仍为整包保存；必须原样携带当前 `transportCycles`，不得通过该入口新增、修改或删除循环。其他扩展资源继续独立保存。循环增改删使用专用接口，避免绕过来源归属及确认校验。刷新方案后使用最新修订号重试冲突操作。

[运输需求](transport-demands.md)按循环内装卸位置身份关联。循环重排、删除位置或删除整个循环时保留已保存的需求；无效引用或装卸倒序显示就绪缺口，等待用户修复或删除需求，不按同名点位自动重新关联。
