# 运输需求与区间日货流

在规划方案中先建立运输循环，再选择“维护运输需求”。每条需求选择所属循环、装货位置、后续卸货位置及日吨数；同一循环可有多组需求，相同起讫也可分别保存。位置显示当前业务序号和名称，例如“1 · 港区”与“4 · 港区”，关联使用稳定的位置身份，顺序调整后不会按名称改绑。

日吨数必须为有限正数，支持小数。需求可在循环尚未确认时先录入，页面会提示业务顺序与回程待确认。日需求允许由后续计划分次运输、同类货物混装及末次不足整车；当前不配置车辆、不生成车次、不检查实际载荷。

## 批量粘贴与保存

在编辑窗口选择循环，粘贴无表头的三列表格，列间使用制表符：装货位置序号、卸货位置序号、日吨数。例如循环“港区→堆场→客户→港区”可粘贴：

```text
1	3	12.5
2	4	7.25
```

先校验并预览，再加入需求草稿；任一行有误会显示行号，修正后重新校验，失败不加入部分行。序号只用于将粘贴行解析成所选循环的当前位置身份。所有表单和粘贴修改都须点击“保存全部需求”才写入本机 SQLite，取消编辑不写入。

保存前由服务端再次校验整批资料、项目归属及修订号；任何错误都不留下部分确认数据。冲突时保留编辑内容，须重新读取最新方案后核对再编辑。重开后需求身份、数组顺序及吨数保持一致。

## 货流依据与就绪缺口

“区间日货流”将每条有效需求的日吨数计入装货位置至卸货位置之间的全部相邻区间，并列出参与需求及吨数作为依据。上例的三个区间分别为 **12.5、19.75、7.25 吨/日**；没有需求经过的区间为零。

循环重排导致装卸倒序、删除装卸位置或删除整个循环时，已保存需求仍保留。页面显示无效引用及就绪缺口，可在维护窗口修复或删除；失效需求不计入区间合计。业务顺序尚未确认与道路、时长不足分别表达；有效的日货流不表示已具备车辆运力或道路就绪。

日货流是每日目标的汇总，不能将其用作车辆可装载量、实际完成量或收入依据。车辆排程及逐车逐区间载荷由后续工单交付。**未校验重卡限高、限重及货车限行**。

## 公开接口与保存结构

`PUT /api/projects/:projectId/scenarios/:scenarioId/demands` 保存整批需求，返回 `200` 和更新后的完整规划方案：

```json
{
  "expectedRevision": 3,
  "demands": [
    {
      "cycleId": "循环标识",
      "loadingPositionId": "装货位置标识",
      "unloadingPositionId": "卸货位置标识",
      "dailyTonnes": 12.5
    }
  ]
}
```

新需求省略 `id`，由服务端生成；已有需求携带本方案内稳定 `id`。省略的原需求删除，空数组删除全部需求；请求数组即保存顺序。装卸位置必须属于指定循环，装货顺序严格早于卸货，不跨循环回绕。重复、未知或其他方案的需求标识及不支持字段被拒绝。

无效行返回 `400` 并注明行号；旧修订号返回 `409`；项目或方案不存在、跨项目操作返回 `404`。有效输入变化只原子递增一次 `inputVersion` 与 `revision`，同内容保存不递增。任何失败保持原数据和版本。

需求保存在方案版本化上下文的可选 `transportDemands` 数组，本功能自 SQLite schema 3 引入，当前 schema 5 另有项目电源和道路资料存储；旧草案缺省此字段。通用 `PATCH context` 必须原样保留当前 `transportCycles` 和 `transportDemands`，不得绕过专用接口校验；其他扩展资源仍可维护。需求读取不发起道路请求，不改变源线路及项目偏好记忆。
