# 逐车运输日计划

规划方案的「每日计划」在人工固定布局的输入下生成运输时间与载荷试算。它不会调整站址、站型或车队数量，也不安排换电、充电或财务。**补能校核未完成，不能据此发布完整物理可行结论。未校验重卡限高、限重及货车限行。**

## 输入和计算依据

先确认闭合运输循环，录入运输需求、可用车辆与运营时间模板，再选择场地及接电关系已确认的固定布局。为当前输入版本显式完成道路准备后即可发起试算。任务保存当时实际采用的道路、上下文和修订号，运行期间使用这份快照。道路采用优先级见[有向道路资料](directed-road-data.md)。

运输就绪检查载重、有效基准起点、班次、装卸耗时与来源。业务区间使用方向、位置和偏好仍有效的实测时间覆盖业务速度，实测耗电的载重依据单独校核。跨线接续及归位使用业务速度，缺失时列出缺口。排程使用车辆身份池中前 `count` 辆。运输试算可以在电池、能耗或财务资料仍待完善时运行。

一个车次完整经过某个循环的固定位置顺序，并返回该循环起点。需求可拆分，同一车次按每个需求经过的区间占用载重，已卸货腾出的容量可供后续装货。每个有作业的点位分别计一次装货和卸货的模板耗时，先卸后装。末次装载剩余需求。吨位累加使用补偿求和，在数值的机器精度范围内消除残差，避免残差额外占用一个车次。

有限贪心构造在可用车辆、班次和循环中选择能够完成并预留归位时间的最早结束车次。完成循环后可跨线接续，班次结束前回基准循环起点；跨线接续和归位的有向道路距离与时间均进入事件及汇总。班次间空档保持在基准起点，无工作事件。算法版本、种子和时限随任务保存；种子影响循环平局顺序，默认 1。默认最长 10 分钟，可设 5–120 分钟，有限构造完成后提前结束。该构造不保证最优，运量缺口不证明无解。

生成器与校验器分离。校验器根据输入、事件及车次重新检查可用车辆、位置连续性、完整循环、装卸顺序、每段载重、需求完成量、同车事件互斥、班次与归位、距离和时间依据。只有通过运输校验的完整结果才发布。

## 公开接口与生命周期

接口前缀为 `/api/projects/:projectId/scenarios/:scenarioId/daily-transport`。

| 方法与后缀               | 行为                                                                         |
| ------------------------ | ---------------------------------------------------------------------------- |
| `GET /`                  | 当前输入版本、就绪缺口、任务摘要及最近完整结果                               |
| `POST /`                 | `{expectedRevision, config?: {seed?, maxRuntimeMs?}}` 创建持久任务并返回 202 |
| `GET /:taskId`           | 读取本项目、本方案下任务及固定输入、进度和结果                               |
| `GET /:taskId?summary=1` | 读取用于轮询的任务状态及进度，省去快照和结果                                 |
| `POST /:taskId/stop`     | 停止该任务并返回方案任务视图                                                 |

应用内仅一个运输计算 Worker 运行，其他运输任务排队；道路准备使用其既有独立队列。启动请求不等待算法完成，页面关闭不停止任务。主线程负责 HTTP、SQLite 和任务发布，纯计算在 Worker 中执行。输入版本变化、冻结、停止或超时后，迟到消息不能发布；复制方案不继承任务或正式结果。只改方案名称不使任务失效。

任务与结果以项目、方案、输入版本及任务身份共同归属，不能通过通用 `context.results` 写成正式结果。失败、停止、超时保留此前完整结果；页面标明其输入版本。服务首次打开 SQLite 后把遗留排队及运行任务标为中断，用户重新试算；不自动恢复指令。数据库 schema 6 从旧版本顺序迁移，保留既有资源及道路任务。

## 页面核对

「每日计划」显示运行状态、算法依据、需求完成量与缺口。缺口分别说明从基准起点直接往返的一趟车次放不进现有班次，或当前构造未安排完。逐车时间轴与事件表列出运输、装卸、跨线空驶和归位，车次区间表列出载重、道路里程、时间及实测或速度来源。循环位置带顺序编号，便于核对同名点位。历史结果按所属输入版本展示。补能校核状态独立显示。

## Worker 交付

应用启动适配层在开发启动与生产构建时，将应用 Worker 和引用的领域源码打包成 `apps/web/.haulpath-workers/daily-transport.cjs`；开发每次启动试算还在独立进程重建，以采用最新领域源码。领域包仍直接消费 TypeScript，不增加预构建。普通生产启动使用构建产物，standalone tracing 和 Docker 显式携带该文件。

产物目标为 Node 22.12 的 JavaScript，不要求 Node 直接读取 TypeScript。[Node Worker 文档](https://nodejs.org/download/release/v22.12.0/docs/api/worker_threads.html)与 [esbuild Node 平台选项](https://esbuild.github.io/api/#platform)是实现依据。实际运行范围与未验证边界见[验收记录](acceptance.md)，不得以加载测试代替整套最低 Node 验收。
