# 年度运输能力

在规划方案内打开“年度能力”，录入各年需求并逐年校核同一固定布局和车队。实际完成量来自完整可重复 24 小时运营日，年度吨数、空驶、换电及购电量由该年代表日的实际账目乘年运营天数形成。需求增长不会自动放大完成量、增车或扩建。**经济校核尚未就绪；未校验重卡限高、限重及货车限行**。

## 年度输入

使用表单或制表符分隔的批量粘贴预览，显式保存年份、运营天数及每条运输需求的日目标吨数。年份是1至9999的唯一整数，按升序保存；不要求连续。运营天数是0至366的整数，不默认365天。日目标沿用运输需求的有限正数规则，零或留空不转换成默认值；零运营天数表示该年不开展业务，年业务数量为零，仍校核代表日能力。零天的年度目标为零，已有完整证据时完成率记100%，界面同时展示日目标与日完成，避免误读。

年度需求引用本方案需求身份，须完整覆盖全部需求，不能按名称重绑。修改循环或需求后保留已保存的年度输入，列失效关联供显式修复。年度输入保存原子检查修订号，真实变化才增加输入版本；通用上下文不能写入 `annualTransport`。旧 `annual` 扩展资料原样保留，不能当作正式年度输入。冻结、复制、比较沿用方案版本规则，副本保留年度输入，不继承计算任务。

输入变化后须在“输入资料”显式准备道路；精确匹配的资料可复用。税费、融资和财务缺失不妨碍物理分析，但已启用的投资、站数、必选及禁选硬约束继续有效。

## 逐年证据与年度账目

每个年度用本年日目标替换需求吨数，其余循环、班次、实测、电池、站型、供电关系、硬约束、绕行和实际道路保持同一任务快照。各年重新寻找周期状态，不连续模拟跨年状态，也不把第一年电量、库存或运量按比例放大。

每条完整证据发布前均独立重放该年运输、能量、工位、库存、连续充电、共享电源及周期初末态，并核对年度乘算。年实际量、缺口及完成率可独立核对；未完成原因来自该年的需求及搜索瓶颈。年度行驶里程使用实际补能时间轴，空驶为载荷为零的行驶里程。年度换电次数使用实际换电次数；购电使用周期 `[0,1440)` 内各电源实际购电之和，不以车辆耗电或待充电量替代。分时电价的后续消费须按该年证据中的具体购电区间与运营天数计算，不能只消费日总量。

同一任务内仅当派生代表日的完整物理快照等价时复用证据；其中包含需求身份与吨数、方向、窗口、实测、全部资源和实际道路。年份、总吨数或站网名称相同不足以复用。运营天数不参与代表日排程，所以可复用相同日证据，但必须重新计算本年的数量。任务固定算法、周期与搜索版本及种子；跨版本不隐式借用历史年度结果。

有周期证据但需求未全部完成表示该候选存在运力缺口。未找到完整周期时，该年的实际量与账目保持空值，不将其解释成零能力或已证明无解。多年总量只累计已有证据的实际吨数；只有全部年度均有完整物理证据才标记多年成果完整，即使部分年度目标未达成。当前任务状态、物理证据完整性和经济状态分别表达。

## 预算、停止与续算

年度任务与每日任务共用单计算 Worker 队列，页面关闭不停止。5–120分钟配置是整个多年任务的总预算，默认10分钟；每年取得剩余预算按剩余年数均分的份额，保存在年度结果 `budgetMs` 中。某年得到完整候选后可继续探索，份额耗尽保留证据再计算后续年；年度评价结束不表示搜索最优。总时限、停止或中断保留已独立校核的年度和当前年度完整候选，未计算年不拼入旧结果。

“继续年度计算”创建新任务，沿用源输入、实际道路、种子和兼容算法。创建事务即保留源年度证据，即使新任务在排队时停止，其后续续算也不会丢失继承成果；本次评价游标与已有证据分开，逐年重放完成前不标记本次多年成果完整。已结束且有完整证据的年度重新校验并保留，正在搜索或未找到的年度重新搜索，继承当前年度已有最佳完整证据；不承诺指令级恢复。输入版本变化、冻结或不兼容算法拒绝续算；迟到消息按任务、项目、方案、输入版本及年份拒收。

任务沿用 SQLite schema6 的运输摘要和详情表，用独立阶段与 `annualResult` 区分年度结果。每日视图不将某年的日吨数选作每日最佳候选，年度视图不跨年比较或跨版本拼装。首次打开数据库将活动年度任务标为中断，保留快照与证据；在线备份和恢复沿用[运行维护](operations.md)。

## 公开接口

前缀 `/api/projects/:projectId/scenarios/:scenarioId/annual-transport`，全部检查项目与方案归属。

| 方法与后缀               | 请求与行为                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `PUT /`                  | `{ expectedRevision, years: [{ year, operatingDays, demands: [{ demandId, dailyTonnes }] }] }` 原子保存，空数组清除年度输入      |
| `GET /`                  | 年度任务摘要、就绪缺口及最近保留的年度结果                                                                                       |
| `POST /`                 | `{ expectedRevision, config?: { seed?, maxRuntimeMs? } }` 异步创建年度任务，返回202；配置阶段如显式提供只能为 `annual-transport` |
| `GET /:taskId`           | 本方案年度任务、不可变快照与 `annualResult`；`result` 为null                                                                     |
| `GET /:taskId?summary=1` | 仅摘要、当前年份、已评价年数及已保留完整证据年数，避免轮询大账目                                                                 |
| `POST /:taskId/stop`     | 停止并保留已校核年度                                                                                                             |
| `POST /:taskId/continue` | `{ expectedRevision, maxRuntimeMs? }` 创建新年度任务                                                                             |

年度结果中的 `evidence` 是该年完整代表日，`reusedFromYear` 指向同任务内等价年份；`economicStatus` 固定为 `not-ready`。未校核年的实际数量字段为null。后续收入与费用应消费本年已校验实际账目，不能将目标吨数当作收入依据。

「运营收支」可显式采用本方案已结束的年度任务，核对实际业务及分时电价；价格变更须通过完整物理输入等价检查，不改写原任务。运营收支完整不改变年度物理任务的 `economicStatus: not-ready`，详见[运营收支](operating-cashflows.md)。

专用资产资本收付不参与代表日物理等价比较；站网原始投资及选址硬约束继续保留。独立资金安排见[资产与资本收付](asset-cashflows.md)。
