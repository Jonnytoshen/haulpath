# 车辆组、电池与运营模板

规划方案内维护给定车队的车辆组、统一电池规格、班次作业窗口及区间实测资料。所有资料通过本机服务保存到方案上下文；当前只维护输入和就绪缺口，不生成逐车排程、补能或可行性结论。**未校验重卡限高、限重及货车限行**。

## 维护与身份

车辆组表示具有相同车型能力、基准循环起点、班次和装卸耗时的一组车辆；同一车型在不同基准循环或班次下可分别建立车辆组。名称可以相同，关联使用稳定标识。每组当日数量是可用上限，允许为零；系统不自动增加车辆。

服务端生成车辆组标识和计划车辆编号。组改名、排序、模板修改不改变编号；减少数量后仍保留历史编号池，仅前 `count` 个可用，再增加时先恢复原编号，超出历史数量才分配新编号。删除整组后重新建立会生成新身份。每个方案历史编号池合计最多10000个，以限制本机展开编号的资源消耗；该限制不是代表验收规模50辆的业务上限。

基准出发和收车位置使用方案内运输循环的起点，保存循环及起点位置身份、坐标依据，不建立独立驻车点。循环换起点、删点、删除或同位置身份的坐标变化，均保留车辆输入并提示修复；不会静默移动基准位置。用户重新选择起点或显式重新确认后才更新依据。

## 参数与单位

方案只使用一份电池规格：容量 `capacityKwh`（kWh）、恒定等效充电功率 `chargePowerKw`（kW）、充电效率 `chargeEfficiency`（大于0且不超过1），并记录来源。容量和功率必须大于零。站型的充电能力、库存及服务窗口由后续工单维护。

每个车辆组保存以下模板及来源：

| 字段                                 | 含义与校验                                                        |
| ------------------------------------ | ----------------------------------------------------------------- |
| `payloadTonnes`                      | 额定载重，吨，大于零                                              |
| `speedKph`                           | 业务速度，km/h，大于零                                            |
| `emptyKwhPerKm`、`fullKwhPerKm`      | 空载、额定满载单位里程耗电，kWh/km，非负，满载不低于空载          |
| `safetySocPercent`                   | 安全电量占统一电池容量的百分比，0–100；合法输入不代表后续运输可行 |
| `loadingMinutes`、`unloadingMinutes` | 每次装货、卸货作业的分钟数，非负；装卸设备排队由本期范围排除      |
| `shifts`                             | 班次作业窗口数组，空数组表示尚未配置                              |

数值未知时用 `null` 保存草案，界面列出缺失项目；不以内置工程参数或零补齐。明确输入的零与缺失值不同。来源说明可在草案中留空并显示缺口。

窗口使用相对代表运营日午夜的整数分钟：`0 <= startMinute < 1440`，`startMinute < endMinute <= startMinute + 1440`。`endMinute` 可以超过1440，例如22:00至次日06:00保存为 `{ startMinute: 1320, endMinute: 1800 }`。窗口不能重叠，跨午夜部分须与下一运营日重复的窗口一并检查；首尾衔接允许相等。不设逐票预约，也不把空窗口解释为全天可用。

## 区间实测覆盖

实测按车辆组、循环及有向相邻的起止位置身份关联；同一组合只能有一份实测。重复地点的不同出现分别维护，反向区间不共用实测。新实测只能选择已经保存的车辆组。

一份实测可覆盖 `durationMinutes`（分钟，大于零），或成对的 `emptyKwh` / `fullKwh`（该区间kWh，非负、满载不低于空载），也可同时填写两类。未覆盖的类别继续使用模板。耗电成对保存，明确对应空载和该组额定满载，不把某一不明载荷下的单次耗电当作所有载荷的依据。实测来源说明必填。

服务端保留区间方向、坐标、规划偏好及额定满载吨数依据。循环重排、删点、改坐标、改偏好或车型额定载重变化后，失效实测继续保存并提示用户重新核对；失效项不能成为有效覆盖。普通保存和修改数值不会自动刷新依据，显式重新确认才能按当前资料更新。删除循环或车辆组也不自动删除实测，用户可修复或删除。

后续计算沿用这些单位与身份：模板行驶分钟数为 `距离米数 / 1000 / speedKph * 60`；模板区间耗电为 `距离米数 / 1000 * (emptyKwhPerKm + (fullKwhPerKm - emptyKwhPerKm) * 实际载荷吨数 / payloadTonnes)`。有效实测时长覆盖时间模板；有效实测空满载耗电按同一载荷比例插值后覆盖能耗模板。道路整数米数、有效实测及来源均应保留，日货流不能替代公式中的实际车次载荷。

例如明确输入40吨载重、30km/h、空满载1/2kWh/km，则10km区间的时间模板为20分钟，20吨车次耗电为15kWh；若该区间实测时长24分钟、空满载耗电12/24kWh，有效覆盖后的时间为24分钟、20吨耗电为18kWh。这里是参数契约算例，不是已交付排程或工程默认值。

## 公开接口及兼容

`PUT /api/projects/:projectId/scenarios/:scenarioId/operations` 提交 `{ expectedRevision, operations }`，其中 `operations` 为整份 `{ battery, vehicleGroups, measuredSegments }`。`battery` 可为 `null`，两个列表可为空；接口整批校验后原子保存并返回完整规划方案。

已有车辆组及实测提交 `id`；新增项省略，服务端生成。输入不得携带 `vehicleIds`、`baseStartBasis` 或实测 `basis`。基准关联变化时生成当前坐标依据；同关联下可用 `refreshBase: true` 显式重新确认。实测关联变化时生成当前区间依据；同关联下可用 `refreshBasis: true` 显式重新确认。重新确认不改变既有计划车辆编号。

未改动的失效关联允许保留，便于继续编辑其他资料；新增、重绑或重新确认必须校验当前方案归属、起点身份和有向相邻关系。未知或重复身份、非法数值及不支持字段返回 `400`，过期修订号返回 `409`；跨项目方案或已删除方案返回 `404`。任一错误不产生部分保存，相同输入不增加版本。

上下文新增可选 `operations` 字段；旧草案没有该字段，读取不回写。本功能在 SQLite schema 3 中引入；当前 schema 4 另含项目电源资源，上下文版本继续为 1。输入变化递增 `inputVersion` 和 `revision`，仅改方案名称保留输入版本。通用方案 `PATCH context` 必须原样保留 `operations`，不能绕过专用校验。循环、需求、源线路及项目偏好记忆保持各自契约。
