# 项目电源接入点

电源接入点在项目基础资料中独立维护，记录供电位置、可用容量及其来源；它不是点位库条目、候选站址或方案内站网。进入项目导航的“电源接入点”即可维护，无须先创建线路或选择规划方案。

## 录入与保存

通过表单输入名称、经纬度和坐标系，可补充可用容量（kW）、容量来源及接入说明；地图配置可用时也可点选位置或搜索地点后填写。坐标系默认 GCJ-02，地图点选使用 GCJ-02。地图缺少配置或加载失败时，表单、列表与批量粘贴仍可使用。

批量粘贴使用七列、Tab 分隔的表格：名称、经度、纬度、坐标系、可用容量 kW、容量来源、接入说明。后 3 列可省略或留空，空容量保留为空；坐标系可留空使用 GCJ-02。整批通过校验后加入草稿，再显式保存电源资料。粘贴按新增资料处理，不以同名点匹配或覆盖身份；修改已有资料使用列表编辑。删除先从草稿移除，显式保存后才写入数据库。

容量必须为非负有限数值，不能填写负数或用名称推断。缺少容量或来源时允许保留待完善资料，并列出具体缺口；容量为 0 时明确显示当前不可供电。资料齐备仅表示位置、正容量及来源已录入，不表示工程可接入、站址已经确认或站网能够运行。接入说明用于记录人工掌握的资料，不自动生成工程结论。

保存后可重开；资源归属和稳定标识由服务端维护。集合修订号防止过时窗口覆盖其他保存，冲突时保留本地草稿，重新加载前核对已有内容。未保存时切换项目、资源或线路会先确认是否放弃草稿；保存期间须等待完成后再切换。资源修改不会自动改写任一规划方案的上下文或输入版本；方案采用的电源快照、站址确认及显式引入更新见[固定布局说明](fixed-station-layout.md)。

## 坐标声明与转换

保存接口接收用户声明的原始坐标，服务端复用既有坐标校验及转换能力。返回资料同时包含 `originalLongitude`、`originalLatitude`、`coordinateSystem` 和供地图使用的 GCJ-02 `longitude`、`latitude`。不能把返回的标准坐标作为原始 WGS84 坐标再次提交。

更新已有点时，原始坐标和声明均未变则复用已有转换结果；仅改名、容量或来源不会重新调用转换。新录或调整的 WGS84 坐标仍需高德 Web 服务配置；配置缺失或任意一批转换失败时，整次保存失败，旧集合保留，不写入半批资料。缺少 JS 地图配置不影响已具备 Web 服务配置的坐标转换，两种配置边界分别处理。

## 公开接口

路径为 `/api/projects/:projectId/power-connection-points`。

| 方法 | 请求                           | 响应                                                |
| ---- | ------------------------------ | --------------------------------------------------- |
| GET  | 无                             | `{ projectId, revision, points }`，空集合修订号为 1 |
| PUT  | `{ expectedRevision, points }` | 整批替换后的集合；省略旧条目表示删除                |

每个写入条目使用 `{ id?, name, longitude, latitude, coordinateSystem, source?, availableCapacityKw, capacitySource, connectionNotes }`。其中经纬度始终为原始声明值，容量缺失使用 `null`；`source` 记录位置录入方式，不能代替容量来源。新条目省略 `id`，已有条目须携带本项目有效标识，不能自造标识或引用其他项目条目。资源、修订号和转换后坐标等服务端字段不接受直接改写。

成功读写返回 `200`，输入或重复标识无效返回 `400`，项目或条目标识不存在及跨项目引用返回 `404`，集合修订号过时返回 `409`；坐标服务错误沿用既有 `502`/`503` 边界。全部条目校验成功并完成必要转换后，事务内再次检查修订号并一次写入；完全相同的集合不增加修订号。当前单次维护最多 1000 项，文本说明最多 5000 字，代表验收规模为 20 个电源。

SQLite schema 4 新增项目电源集合表，升级保留已有项目、线路、点库、方案和偏好。删除项目同时清理其电源资源；备份及恢复继续操作整个 SQLite 数据库，遵循[运行维护](operations.md)。升级前应保留可用备份，旧应用不支持打开 schema 4 数据库。
