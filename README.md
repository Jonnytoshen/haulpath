# 重途·HaulPath

个人使用的本机中文网页工作台，按项目整理重卡业务的行前线路、点位与里程测算。支持有序多点规划、地图预览、Excel / CSV / KML / KMZ 点位导入，以及单线路和项目 Excel 导出。

中文名称为“重途”，英文名称为“HaulPath”，仓库名称为 `haulpath`。

标志、颜色、字体来源与资产使用方式见[品牌标志规范](docs/brand.md)。

**未校验重卡限高、限重及货车限行。** 首版采用高德普通驾车规划 2.0，按相邻点位分别规划后汇总；不保证重卡可通行，不提供实时导航，也不自动优化点位顺序。

## 本机启动

准备 Node.js **22.12.0 或更高版本**、pnpm **12.10.1**（最低 12）。在仓库根目录执行：

```sh
pnpm install --frozen-lockfile --ignore-scripts
test -e .env.local || cp .env.example .env.local
```

在 `.env.local` 填写自己的高德凭证：

| 变量 | 用途 |
| --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 服务端驾车规划、WGS84 坐标转换 |
| `AMAP_JS_KEY` | 高德 JS API 2.0 地图、地点搜索；浏览器可见 |
| `AMAP_JS_SECURITY_CODE` | 与 JS Key 配套的安全密钥，服务端通过受控代理使用 |
| `HAULPATH_DB_PATH` | SQLite 路径，默认 `./data/haulpath.sqlite`；相对路径以启动目录为准 |

Web 服务 Key 与 JS 安全密钥不发送到浏览器。请按高德控制台要求配置对应服务权限与本机访问来源。无凭证时仍可管理项目、线路草稿、GCJ-02 点位及导出；地图、规划和 WGS84 转换会提示缺少相应配置。

配置完成后构建并启动：

```sh
pnpm run build
pnpm run start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。应用默认只监听本机 `127.0.0.1`。端口占用时可以使用 `pnpm run start --port 3001`。环境变量修改后需重启服务；`build` 使用 `next build --webpack`。

项目资料保存在本机 SQLite，默认位置为 `data/haulpath.sqlite`。**同一数据库仅运行一个应用服务**，包括不同端口、开发与生产模式和不同工作副本；切换前先停止原服务。数据位置、备份与恢复见[运行维护](docs/operations.md)。

## 使用流程

进入项目先显示“线路总览”，每条线路一行，可按线路或任意点位名称搜索、按结果状态筛选，并按名称、有效里程或结果时间排序。表格展示名称、有序点位、点位数、偏好、状态、总里程和北京时间；长点位列表默认两行，可展开核对。桌面表头固定，窄屏在表格内横向滚动。

点击线路名称或侧栏线路进入该线路的任务画布，打开或新建线路后默认显示“编排点位”。通过“编排点位 / 测算线路 / 核对方案”切换当前任务，侧栏仍可快速切换线路。返回总览保留当前项目会话内的搜索、筛选、排序、展开和双向滚动，切换项目或刷新页面后清空；删除线路后回到总览。手机通过顶部菜单展开项目与线路。

“项目点位库”是与线路总览并列的项目资源入口。独立管理时不会选中某条线路，也不显示线路地图和方案。从线路中点击“从点位库选择”则进入全页选择模式，持续显示目标线路和已添加点数；可连续选点，再点击“返回线路点位”回到编排。

1. 新建或选择项目，从总览核对已有线路，或创建命名线路；线路可以先保存为空草稿。
2. 在“编排点位”中手动输入坐标，或从项目点位库选择，按实际行驶顺序整理起点、途经点和终点。可拖动或使用上下移按钮排序。移除点位后可撤销最近一次移除，并保留之后的编辑；关闭提示、再次移除或切换项目／线路会结束该次撤销。
3. 需要整理公共地点时进入项目点位库。导入 `.xlsx` 或 UTF-8 CSV 时可下载模板、选择工作表、映射名称/经度/纬度列并声明坐标系；导入 UTF-8 `.kml` 或 `.kmz` 时只读取地标中的 Point，多个 KML 文档的 KMZ 需先选择一个。预览错误项并确认选中的有效点位后写入点位库，再按需选入线路；选入后独立维护。永久删除点库点位前需确认，已选入线路的副本保留。
4. 进入“测算线路”，在地图中核对或通过地点搜索、地图选点补充点位，在[规划偏好](#规划偏好)中选择一项，再手动开始规划；当前页显示区间进度。配置读取中或缺少 Web 服务 Key 时，规划入口禁用并就地提供配置说明；仅缺少 JS 地图配置不阻止服务端测算。N 个点计算 N−1 个区间，各区间使用同一偏好。
5. 进入“核对方案”，查看地图、线路总里程和区间明细，它们使用同一份完整成功方案。修改点位、顺序或偏好后显示“待重算”，旧折线退出预览、当前里程留空。成功重算后整体替换方案；失败保留最近成功方案。仅改线路名称保留当前任务页，不会使结果失效。
6. 在“核对方案”中导出当前线路，或回到项目层导出整个项目。“导出项目”始终包含全部项目线路，不受网页搜索、筛选和排序影响。得到“线路总览”和“区间明细”双表；里程为公里数值，显示三位小数。未规划、待重算线路保留总览状态但不输出有效里程和区间。导出和重开线路均不触发自动规划。

总览在进入、窗口聚焦或手动刷新时读取最新数据；有规划任务时持续更新，隐藏时暂停、恢复可见后刷新。读取失败保留已有内容并提示重试。结果状态与任务提示分别展示：同输入重算失败仍可显示有效旧里程；未规划、待重算的当前里程和有效结果时间显示“—”。浏览和刷新不会自动算路，也不改变项目记住的偏好。

手动输入和表格坐标系由用户声明，默认 GCJ-02；标准 KML/KMZ 固定使用 WGS84。WGS84 在保存手动点位或确认导入时经高德转换，同时保留原始坐标；导入转换失败不写入半批数据。KML/KMZ 支持标准 2.2/2.3 命名空间，文件最多 10 MiB，KMZ 内所选 KML 解压后最多 20 MiB，预览数据最多 20 MiB；线、面、轨迹及网络链接不会导入，高程、描述、样式和文件夹信息不保存。每次导入均追加点位，不自动去重。支持 A→B→A 往返，相邻重复坐标须先调整。首版不支持旧 `.xls`、纯地址批量定位、多用户、云同步或离线地图。

项目、点库、线路及最近成功方案由本机服务写入 SQLite；更换浏览器不丢失项目数据。请阅读 [备份、恢复与配置排查](docs/operations.md)，备份时不能在线直接复制 SQLite 主文件。

## 规划偏好

支持高德普通驾车 v5 文档列出的全部 17 项策略。原生下拉框按下列顺序分组，选择后显示当前项的简短说明；每次选择一个完整策略，整条线路统一使用。

| 分组 | 选项 |
| --- | --- |
| 常用偏好 | 高德推荐、躲避拥堵、高速优先、不走高速、少收费、大路优先、速度最快 |
| 组合偏好 | 躲避拥堵＋高速优先、躲避拥堵＋不走高速、躲避拥堵＋少收费、少收费＋不走高速、躲避拥堵＋少收费＋不走高速、躲避拥堵＋大路优先、躲避拥堵＋速度最快 |
| 其他策略 | 速度优先、费用优先、常规最快 |

“速度优先”“费用优先”“常规最快”按高德文档只返回一条路线；其他策略仍按既有规则采用各区间返回的第一条方案。“少收费”不等于不走收费路段，也不把任何策略解释为距离最短或重卡通行保证。策略含义以[高德路径规划 2.0 文档](https://developer.amap.com/api/webservice/guide/api/newroute)为准。

新建线路沿用同一项目最近成功保存的偏好，不等待规划成功。新项目和升级后的已有项目先从“高德推荐”开始记忆，已有线路及成功方案保持原样。仅打开旧线路、改名、编辑点位、规划或导出不会改变这份记忆；删除线路甚至删空线路后仍保留，项目之间互不影响。记忆保存在 SQLite 中，随重启、更换浏览器和备份恢复延续。

通过接口创建线路时，省略 `strategy` 会继承项目记忆；更新线路时省略该字段会保留原值且不更新记忆。显式成功保存合法 `strategy`（包括同值）会更新项目记忆；同值不会使线路结果失效。保存失败时线路与记忆均不改变，后续规划失败也不撤销已保存的选择。

## 开发与验证

项目使用 Next.js App Router、TypeScript、SQLite / better-sqlite3、ExcelJS；界面采用 shadcn/ui、Tailwind CSS 和 Lucide Icons。开发时使用以下入口，默认同样只监听本机；端口可通过 `--port 3001` 指定：

```sh
pnpm run dev
```

验证入口：

```sh
pnpm run typecheck
pnpm run build
pnpm run test:api
pnpm run test:browser
pnpm run test:commits
pnpm run test:release
# 一次串行运行全部测试文件（分类入口存在交叉）：
pnpm test
```

API 与浏览器测试会启动真实本机应用并使用临时 SQLite，下载和读取实际 Excel 文件；仅高德 HTTP 服务及地图 SDK 使用可控替身。浏览器测试默认使用已安装的 Google Chrome；可用 `PLAYWRIGHT_CHROMIUM_CHANNEL` 选择其他已安装的 Playwright 浏览器 channel。请先停止当前工作副本的开发或生产服务，再串行运行这些命令，避免多个服务共享 `.next`。

生产中断恢复用例先执行 webpack 构建，使用临时生产服务和真实浏览器验证重启及备份恢复后的手动重试，因此 `test:api` 与 `test:browser` 都需要系统 `sqlite3` 和已安装的浏览器。该用例在两个分类入口中有交叉；`pnpm test` 按文件只执行一次。

[验收记录](docs/acceptance.md) 按日期与代码基线记录完整闭环、代表规模、发布与品牌验证及其证据边界。**真实高德联调尚未执行**：需要配置真实凭证后完成[人工联调清单](docs/acceptance.md#待真实凭证的人工联调)；模拟测试不证明真实地图、搜索或重卡通行可用。

提交前阅读 [Angular 扩展提交约定](docs/agents/git-commits.md)。若使用上述跳过生命周期脚本的安装命令，需要安装或修复提交 hook 时显式执行 `pnpm run prepare`；已启用独立 worktree 配置时使用该文档中的 `GIT_CONFIG` 命令。领域术语见 [GLOSSARY.md](GLOSSARY.md)，架构取舍见 [ADR](docs/adr/)；需求和工单按本地 [tracker 约定](docs/agents/issue-tracker.md) 管理。

## 软件发布

使用本机 Nx Release 工作流；先以 `pnpm run release --first-release --dry-run` 预览首个 `0.1.0` 正式基线。后续支持自动版本、位置参数 `patch` / `minor` / `major` / `X.Y.Z`、`--channel stable|alpha|beta|rc` 及 `--dry-run`；API 失败后使用 `pnpm run release:resume <目标tag>` 补建。完整门禁、认证、候选规则和精确恢复步骤见[发布指南](docs/releasing.md)。

发布仅维护源码版本、日志、Git tag 与 GitHub Release，始终跳过 npm 发布，不生成安装包或自动部署。历史验证基线与真实服务联调边界见[验收记录](docs/acceptance.md)。
